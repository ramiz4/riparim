# Locale foundation

Issue #47 uses one native `app/[locale]` page tree on Vinext 1.0.0-beta.5.
Public German URLs keep their existing paths; the proxy rewrites German pages
internally to `/de`. Albanian and English pages use `/sq` and `/en`. Public
`/de` URLs receive a 308 to the equivalent German URL. The allowlist is
`de | sq | en`; no browser-language detection or saved language preference is
introduced. APIs, `/auth/bestaetigen`, native ChatGPT endpoints, static assets,
`/_next` and technical metadata stay outside the rewrite.

## Verified runtime boundaries

Before moving the page tree, a minimal native route/layout/message was tested
on the installed Vinext version in its actual local Worker. Direct SSR and RSC
requests on DE/SQ/EN, the DE rewrite, normalization and unknown paths passed;
a real Sites production build and the bundled Link regression also passed.

The retained `tests/i18n-worker.test.mjs` executes each actual production bundle
with native D1/R2 and local assets. It initializes only an isolated database;
all external requests are rejected. It verifies concurrent DE/SQ/EN SSR/RSC,
HTML language/title/selected language, published/missing/invalid/draft profiles,
308, 404, APIs, callback privacy and assets. Both build targets run this test.
`tests/production-navigation.test.mjs` exercises the actual bundled Vinext Link
on locale paths, query/hash, keyboard activation and failed prefetch. The
vendor Link chunk stays separate after adding the thin localized Link wrapper.

Two concrete beta.5/runtime differences are covered:

- A production route miss after an internal rewrite returned `Not Found` with
  HTTP 200. The proxy now rejects unknown page shapes with an explicit 404
  before rewriting, including unknown dotted paths and locale-prefixed asset-like
  paths. The matcher includes these suffixes; only actual physical public files
  and bounded technical metadata paths bypass that gate, without any auth
  database/provider lookup. `publicAssetPaths` is checked against the actual
  `public/` file inventory: update it when adding/removing a physical asset.
  Recognized profile paths still use the existing server
  database/publication gate; nonexistent, invalid and draft profiles return 404.
- Local workerd supports Albanian plural rules but omits Albanian number/date
  ICU data. `formatDate` uses the equivalent native German numeric date format
  for that runtime. `formatNumber` uses native Intl rounding and format parts,
  with Albanian separators/grouping when sq data is unavailable. Full-ICU
  browsers and the Worker return the same strings. Date-only values are
  validated as calendar dates and retain their day; timestamps use
  `Europe/Belgrade`.

## Shared contracts and follow-up ownership

- `lib/i18n/locale.ts`: `Locale`, `locales`, `defaultLocale`, `isLocale`,
  `localeFromPath`, `stripLocalePrefix`, `localizeHref`, technical/page paths.
  Add new page shapes here when adding native pages.
- `lib/i18n/messages.ts`: typed JSON common/metadata catalogs,
  `getMessages(locale, namespaces)`, `createTranslator(messages)` and a German
  common fallback. The route layout serializes only the active common catalog;
  metadata stays server-side. The browser translator bundle omits other locale
  catalogs. Feature issues should keep public/customer/management/mail messages
  in their own namespace modules and serialize only their required active
  catalog, preserving this common provider contract.
- `lib/i18n/client.tsx`: `I18nProvider`, `useI18n()` returns `locale`, `messages`
  and typed `t`. Rich text composes React nodes/links; no translated HTML or
  general ICU parser is used.
- `components/locale-link.tsx` and `locale-anchor.tsx`: localized client and
  explicit document links. `WorkshopNavigationLink` retains its original
  stalled-render fallback and recognizes locale-prefixed profile/catalog pages.
  `catalogueHref(filters, locale)` defaults to German compatibility.
- `lib/auth/return-path.ts`: pure `validatedReturnPath`; server
  `safeReturnPath` remains the auth boundary and supplies the configured origin.
  Both reject native/locale-prefixed/encoded callback loops and external URLs.
- `lib/i18n/navigation.ts`: `languageSwitchHref` keeps the profile and permitted
  public filters/section hashes/safe `weiter` target. It drops token/private
  fields and submission IDs. Consultation `sprache=sq` is independent of UI
  locale. There is no new URL/browser-storage/provider channel for private
  vehicle/problem/evidence fields.
- `lib/i18n/navigation-guard.tsx`: existing forms call
  `useNavigationGuard({dirty,busy})`. Only booleans enter this request-local
  React context. `LanguageSwitcher` uses document navigation, asks a localized
  explicit discard confirmation and supports cancellation. Uploads, mutations,
  logout/OAuth/reauth/account deletion disable it until completion; successful
  outgoing OAuth/document navigation stays busy through unload.
- `lib/i18n/values.ts`: `valueLabel`/`displayLabels` separate existing canonical
  values from translated labels. `Picker.valueCategory` and its existing
  `displayLabels` leave selected values/API payloads unchanged. The common
  `approved` status means the review's `Bewertung vervollständigen`; business
  approval needs its own contextual message in that feature namespace.
- `lib/i18n/codes.ts`: safe `ErrorCode`, `MessageCode`, `CodedResponse` and
  translator-based fallback helpers. Follow-up API migrations retain legacy
  `error`/`message` and HTTP status while adding codes. Provider text must never
  become a code. `localeNotice=preference_not_saved` shows a localized notice;
  future account-preference writes belong to the customer issue. Exclude this
  parameter from future canonical/alternate URLs.

Full public/customer/management text, SEO, persistent account language and
transactional mail localization belong to the linked follow-up issues.
Foundation introduces no package, schema migration or production change.

## Validation and TDD evidence

`npm test` runs catalog/key/placeholder/nonempty checks and compiler probes plus
locale proxy, safe-return/navigation, language-control, Google SDK-language and
message/value/format/code tests. The first proxy test failed because no German
rewrite existed; it passed after response-plan composition. The first safe
return regression failed because a prefixed callback was accepted; it passed
after the shared auth boundary. Message/namespace/plural, value/Intl/code and
client-bundle tests were developed in RED/GREEN steps. Production tests caught
and fixed the route-miss HTTP status and missing sq ICU behavior described above.

The standard checks remain installation, catalog validation, `npm test`,
TypeScript, ESLint, both real production builds and each release package.
Browser QA covers the shared header/language selector at 390 and 1280 pixels,
Light/Dark/System, keyboard and 200% zoom. No real accounts, emails, uploads or
provider changes are used by these fixtures.

## Customer locale contract

Issue #50 adds the `customer` namespace, scoped to Auth/account screens and the
public pages that contain private review dialogs. Root layout still serializes
only active common messages. `I18nMessages` extends the existing request-local
provider without replacing its navigation guard; client translators do not
import inactive feature catalogs.

`lib/auth/locale.ts` owns validated request/callback locale and the locale-first
`authCallbackUrl` shared with Auth mail templates. URL locale wins over a
conflicting safe return prefix. Callback, PKCE/deletion cookie paths, provider
identities, ownership and canonical visit fields stay stable. Review messages
and source-owned `ValidationError.code` are additive to legacy API strings.
Clients select safe local text from codes, never from raw provider messages.

Signup stores `user_metadata.preferred_locale`; only the verified own confirmed
account may change it through the independent `{preferredLocale}` PATCH.
Recovery does not change metadata. Explicit language navigation attempts this
presentation preference with a bounded timeout; URL remains authoritative and
`localeNotice=preference_not_saved` survives reload on failure. It never grants
roles or ownership. `lib/i18n/delete-confirmation.ts` owns exact visible deletion
phrases and maps a confirmed input to the existing canonical server sentinel.
`evidenceHref` adds the optional download locale without changing binary content
or permissions; plain text errors add `X-Riparim-Error-Code`.

## Business and administration locale contract

The `management` namespace covers ownership requests and drafts, workshop
editing, user roles, review moderation, Auth setup and delivery diagnostics.
These request-local pages add only active management/customer messages (and
public messages for their shared footer). Business and all management routes
are `noindex,nofollow` and expose no public language alternatives.

Editors always receive original approved fields; translated labels never replace
workshop descriptions, notes, source titles, services, language values, provider
identities, roles or revision guards in mutations. Private operator/moderator
text remains original and stays in the current document. Forms share the
foundation's dirty/busy navigation guard. Notification state/error codes remain
stable; display messages distinguish provider acceptance from delivery and
format attempts and Kosovo retry timestamps in the active locale.

Profile and business sources assign typed `ValidationError` codes, and mutation
APIs retain legacy text/status while adding `errorCode`/`messageCode`. Clients
select local messages by codes and never display raw provider errors. Account
renames update only `full_name`, relying on the provider's documented metadata
key-merge contract rather than replaying an older profile snapshot. Isolated
fixtures cover a concurrent preference/metadata update; this is not a test of
concurrent production Supabase database transactions.

Auth setup consumes the central confirmation/recovery subject and HTML exports
as technical Go source. Four separately labelled copy controls preserve their
exact bytes; the source itself is never translated or rendered as markup.
Instructions require the actual canonical `SITE_ORIGIN`/provider Site URL,
preserved callback permissions, a verified release export with Go previews,
paired subject/body activation, byte-exact readback and isolated receipt tests.
A German fallback is not accepted as evidence of Albanian/English rendering.
